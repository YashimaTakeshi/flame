# 追加実測: グレインの解像度一致

測定日: 2026-09-21 / Chromium 141 / 再現コード: `scratchpad/grain/{page.html,page2.html}`

## なぜ測ったか

PoC（`report-canvas.md`）で「グレインを素朴に実装するとプレビューと書き出しが一致しない」
ことが判明していた。設計案Cと案Bがそれぞれ別の解法を提案し、**食い違った**ため実測で決着させた。

- 案Cの仮説: ノイズを「出力ピクセル位置」でなく**論理セル座標**で索けば解像度非依存になる
- 案Bの仮説: グレインのタイルを**書き出しの倍率で1度だけ生成**し、プレビューでは
  **同じタイルを縮小して敷く**（縮小のならしを両方に効かせる）

## 測り方

幅1000論理単位(lu)の座標系で、プレビュー幅800px（k=0.8）と書き出し幅6000px（k=6）に
同じ内容を描く。書き出しをプレビュー相当に縮小し、両者の「粒の強さ」
（横方向の隣接ピクセル差の平均）を比べる。比が 1.0 なら完全一致。

## 結果1: 案Cの方式（論理セル座標の疑似乱数）

| セル寸法 | プレビューの粒 | 書き出しを縮小した粒 | 一致率 |
|---|---:|---:|---:|
| 素朴（出力ピクセル位置） | 18.668 | 2.123 | **0.114** |
| 0.5 lu | 18.658 | 5.356 | 0.287 |
| 1.0 lu | 18.650 | 8.732 | 0.468 |
| 1.5 lu | 15.533 | 9.226 | 0.594 |
| 2.0 lu | 11.626 | 9.436 | 0.812 |
| 3.0 lu | 7.753 | 6.894 | 0.889 |
| 4.0 lu | 5.805 | 5.539 | 0.954 |

**部分的にしか正しくない。** 素朴実装の0.114から大きく改善するが、一致率が実用水準に達するのは
セルを 3〜4 lu まで粗くしたときだけ。4 lu は書き出し時に 24 デバイスピクセル角で、
フィルム粒子ではなくモザイクになる。**粒子に見える細かさ（0.5〜1.5 lu）では 0.29〜0.59 にとどまる。**

## 結果2: 案Bの方式（タイルを書き出し倍率で作り、プレビューは縮小して敷く）

| タイル寸法 | プレビューの粒 | 書き出しを縮小した粒 | 一致率 |
|---|---:|---:|---:|
| 256 px | 3.060 | 2.991 | **0.977** |
| 512 px | 3.001 | 2.948 | **0.982** |
| 1024 px | 3.016 | 2.973 | **0.986** |

**1粒＝1デバイスピクセルという最も細かいグレインで 0.98 に達する。** タイル寸法の影響は小さく、
512角で十分（1024にしても0.004しか改善しない）。

## 採用する方式

**案Bの方式を採る。**

1. グレインのタイル（512角）を**書き出しの倍率で1度だけ生成**し、キャッシュする
2. 書き出しでは 1:1 で敷く
3. プレビューでは**同じタイルを `k_preview / k_export` 倍に縮小**して敷く。
   `imageSmoothingQuality = 'high'` を有効にし、**縮小のならしを両方に通す**

一致しない原因は「乱数の索き方」ではなく「**書き出し側だけが縮小のならしを通っていたこと**」だった。
プレビュー側にも同じならしを通せば揃う。

## 補足

案Bの方式ではプレビューの粒の絶対値が下がる（18.6 → 3.0）。これは劣化ではなく、
**縮小後の見え方を正しく再現している**ということ。利用者が画面で見ている粒の強さが、
保存される画像の粒の強さと一致する。

タイル方式は実測で 1.7ms（`report-canvas.md`）であり、ImageData 直接操作の 809ms に対して
476倍速い。性能と一致の両方でタイル方式が優る。
