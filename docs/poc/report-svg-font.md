# 追加実測: SVG 縦書きのフォント欠落（案Bの FM-07 の検証）

測定日: 2026-09-21 / Chromium 141 / 再現コード: `scratchpad/svgfont/{run.mjs,perf.mjs}`

## なぜ測ったか

設計案B だけが指摘した罠（FM-07）:
「`<img>` 化した SVG は外部 Web フォントを読まないため、縦書きキャプションだけが
フォールバック書体で書き出される」。
他の2案は見落としており、事実なら差別化機能 D1（日本語・縦書き）が壊れる。未実測だったので測った。

## 測り方

1. 和文サブセット（かな・記号 58KB）を `FontFace` で**親文書に登録**し、`document.fonts.ready` まで待つ
2. 同じ書体名を `font-family` に指定した SVG を3通り作り、`<img>` 経由で canvas に描いて画素を比較
   - **A**: 親文書に登録した書体を SVG から参照（埋め込みなし）
   - **B**: SVG 内に `@font-face { src: url(data:font/woff2;base64,...) }` で埋め込み
   - **C**: 素の `serif`（フォールバック基準）

## 結果: FM-07 は実在する

| 描画 | 黒画素数 | 重心X | 重心Y |
|---|---:|---:|---:|
| A: 親文書の FontFace を参照 | 1,388 | 98.57 | 205.66 |
| C: 素の serif（フォールバック基準） | 1,388 | 98.57 | 205.66 |
| B: SVG 内に data: URI で埋め込み | 1,491 | 99.33 | 171.17 |

| 比較 | 相違画素数 |
|---|---:|
| **A vs C（フォールバック）** | **0** |
| A vs B | 3,545 |
| B vs C | 3,545 |

**A は C と1画素も違わない。SVG は親文書に登録した書体を一切見ていない。**

さらに悪いことに、**同じページで Canvas の `fillText` は正しく効いている**
（実測幅: TestJP 308.00 / serif 315.22 で有意に異なる）。つまり：

> **横組みキャプションは正しい書体、縦組みキャプションだけフォールバック書体**という、
> 1枚の画像の中で書体が食い違う壊れ方をする。例外も警告も一切出ない。

`report-fonts.md` で判明した「フォント読み込みを待たずに描くとフォールバックになる」罠とは
**別経路の、同じ種類の失敗**である。待っていても起きる。

## 対処と、その costの実測

対処は **SVG 内にフォントを `data:` URI で埋め込む**こと。base64 で約4/3 に膨らむ。
プレビューは設定変更のたびに再生成されるため、実用速度に耐えるかを測った
（20回のラスタライズの平均、ウォームアップ後）。

| 埋め込む書体 | SVG 文字列長 | 1回あたり |
|---|---:|---:|
| なし（serif） | 264 | 1.16 ms |
| かな・記号のみ 58KB | 78,568 | 3.88 ms |
| **第一水準込み 463KB** | **632,360** | **12.34 ms** |

**実用に耐える。** 12.34ms は1フレーム（16.7ms）に収まる。さらに、縦書きキャプションは
テキストか書体設定が変わったときだけ再生成すればよく、生成結果の画像をキャッシュすれば
通常のプレビュー再描画では実質ゼロになる。

## 実装に落とす規則

1. **縦書き SVG には必ずフォントを `data:` URI で埋め込む。** 親文書の `FontFace` は届かない。
2. **埋め込み忘れを検知する。** 「`font-family` を指定した版」と「指定を外した版」を描いて
   画素が一致したら、埋め込みが効いていない（＝フォールバックで描かれた）と判定できる。
   この検証は実測で機能することを上の A vs C で確認済み。
3. 和文の base64 文字列は1度だけ作ってキャッシュする（632KB の文字列を毎回作らない）。
4. 縦書きキャプションのラスタライズ結果は、テキスト・書体・サイズをキーにキャッシュする。
