# 要件定義

最終更新: 2026-09-21

## 1. 何を作るか

自分で撮影した写真に、**EXIF 由来のキャプションを添えたフレーム**を合成して書き出す
スマートフォン向け Web アプリ（PWA）。

参考アプリ: FRMM（iOS）。構造の分析は `reference-frmm.md`。

## 2. 利用者

**2モードを用意する。**

| モード | 想定利用者 | 設計の重心 |
|---|---|---|
| こだわる | ミラーレス一眼などで撮り SNS に上げる層 | レンズ名・露出設定・焦点距離が意味を持つ。キャプションが主役 |
| お手軽 | iPhone で撮る一般層 | 「いい感じの枠」が主役。EXIF は日付程度に抑える |

初回起動時にどちらかを選ばせ、表示する設定の粒度を変える。あとから切り替え可能。

## 3. 設計原則（交渉の余地なし）

1. **写真は一切サーバーに送らない。** EXIF 解析・合成・書き出しをすべてブラウザ内で完結させる。
   外部通信が発生する機能を足す場合は、**何をどこへ送るかを画面に明記**する。
2. **プレビュー＝書き出し結果。** 画面に見えているものと保存される画像が一致しないなら、
   その機能は未完成とみなす。
3. **描画コアは環境非依存に保つ。** 将来のネイティブ配信に備え、
   「描画命令を組み立てる層（純 TypeScript・DOM 非依存）」と「それを実行する層（Canvas 2D）」を分離する。

## 4. 機能

### 4.1 参考アプリから踏襲する5軸

| 軸 | 内容 |
|---|---|
| Style | キャンバス比＋配置テンプレート。**15種すべて再現**（OR1-3 / SQ1-4 / TF1 / FF1-3 / NST1 / STN1-3） |
| Layout | 整列（Left/Center/Right）、字間（Tight/Normal/Wide/Widest）、文字サイズ（Small/Medium/Large） |
| Color | ボーダー（Standard/Bordered）、背景色（White/Black/Ivory/Warm White/Gunmetal/Onyx/Silver Sand/Sunny Yellow/Sakura ほか） |
| Font | 欧文書体の選択。**背景が暗色ならキャプション文字色を自動反転** |
| Info | Title / Artist / Date と、カメラ機種・レンズの手動上書き。組み合わせを**プリセットとして保存** |

### 4.2 独自の差別化（4つとも入れる）

| # | 機能 | 狙い |
|---|---|---|
| D1 | **日本語・縦書き対応** | 参考アプリは欧文書体のみ。和文書体と縦書きキャプションで日本語圏に効く |
| D2 | **フィルム風の質感フレーム** | 粒子（グレイン）、印画紙風のフチ、ネガのコマ枠など。参考アプリは完全にフラット |
| D3 | **複数枚の一括処理** | 同じフレームをまとめて適用・一括保存。旅行後に30枚処理する実用場面 |
| D4 | **撮影地の表示** | EXIF の GPS から地名をキャプションに入れる。※ 設計原則1との整合を要確認 |

## 5. 配布

- **URL で広く公開。** 静的ホスティング（Cloudflare Workers 等）。
- GitHub に push すると自動デプロイされる状態まで敷設する。手動デプロイで終わらせない。
- PWA としてホーム画面に追加できるようにする。
- 将来のネイティブ配信も視野に入れるが、MVP のスコープ外。

## 6. スコープ外（現時点）

- 写真の現像・色調整（露出・コントラスト等）
- アカウント機能、クラウド保存
- 課金機能（参考アプリは買い切り¥1,500／月額¥200 だが、MVP では扱わない）

## 7. 未確定（技術検証の結果を見て決める）

- 欧文8書体をどのオープンライセンス書体で代替するか
- 和文フォントの配信方式（初回ロード量との兼ね合い）
- 縦書きの実現方式
- 撮影地の地名をオフライン同梱で引くか、外部 API を使うか（プライバシーとのトレードオフ）
- 一括処理の同時枚数上限
