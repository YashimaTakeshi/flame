# 要件定義

最終更新: 2026-09-21

## 1. 何を作るか

自分で撮影した写真に、**EXIF 由来のキャプションを添えたフレーム**を合成して書き出す
スマートフォン向け Web アプリ（PWA）。

参考アプリ: FRMM（iOS）。構造の分析は `reference-frmm.md`。

## 2. 利用者

**2モードを用意する。**

| モード | 想定利用者 | 設計の重心 |
|---|---|---|
| こだわる | ミラーレス一眼などで撮り SNS に上げる層 | レンズ名・露出設定・焦点距離が意味を持つ。キャプションが主役 |
| お手軽 | iPhone で撮る一般層 | 「いい感じの枠」が主役。EXIF は日付程度に抑える |

初回起動時にどちらかを選ばせ、表示する設定の粒度を変える。あとから切り替え可能。

## 3. 設計原則（交渉の余地なし）

1. **写真は一切サーバーに送らない。** EXIF 解析・合成・書き出しをすべてブラウザ内で完結させる。
   外部通信が発生する機能を足す場合は、**何をどこへ送るかを画面に明記**する。
2. **プレビュー＝書き出し結果。** 画面に見えているものと保存される画像が一致しないなら、
   その機能は未完成とみなす。
3. **描画コアは環境非依存に保つ。** 将来のネイティブ配信に備え、
   「描画命令を組み立てる層（純 TypeScript・DOM 非依存）」と「それを実行する層（Canvas 2D）」を分離する。

## 4. 機能

### 4.1 参考アプリから踏襲する5軸

| 軸 | 内容 |
|---|---|
| Style | キャンバス比＋配置テンプレート。**15種すべて再現**（OR1-3 / SQ1-4 / TF1 / FF1-3 / NST1 / STN1-3） |
| Layout | 整列（Left/Center/Right）、字間（Tight/Normal/Wide/Widest）、文字サイズ（Small/Medium/Large） |
| Color | ボーダー（Standard/Bordered）、背景色（White/Black/Ivory/Warm White/Gunmetal/Onyx/Silver Sand/Sunny Yellow/Sakura ほか） |
| Font | 欧文書体の選択。**背景が暗色ならキャプション文字色を自動反転** |
| Info | Title / Artist / Date と、カメラ機種・レンズの手動上書き。組み合わせを**プリセットとして保存** |

### 4.2 独自の差別化（4つとも入れる）

| # | 機能 | 狙い |
|---|---|---|
| D1 | **日本語・縦書き対応** | 参考アプリは欧文書体のみ。和文書体と縦書きキャプションで日本語圏に効く |
| D2 | **フィルム風の質感フレーム** | 粒子（グレイン）、印画紙風のフチ、ネガのコマ枠など。参考アプリは完全にフラット |
| D3 | **複数枚の一括処理** | 同じフレームをまとめて適用・一括保存。旅行後に30枚処理する実用場面 |
| D4 | **撮影地の表示** | EXIF の GPS から地名をキャプションに入れる。※ 設計原則1との整合を要確認 |

## 5. 配布

- **URL で広く公開。** 静的ホスティング（Cloudflare Workers 等）。
- GitHub に push すると自動デプロイされる状態まで敷設する。手動デプロイで終わらせない。
- PWA としてホーム画面に追加できるようにする。
- 将来のネイティブ配信も視野に入れるが、MVP のスコープ外。

## 6. スコープ外（現時点）

- 写真の現像・色調整（露出・コントラスト等）
- アカウント機能、クラウド保存
- 課金機能（参考アプリは買い切り¥1,500／月額¥200 だが、MVP では扱わない）

## 7. 技術検証を受けて確定した方針

実測の根拠は `poc/` の4レポート。

| 論点 | 決定 | 根拠・代償 |
|---|---|---|
| EXIF 読み取り | `exifr` の lite ビルド | gzip 14.6KB。他2ライブラリはレンズ名が取れず落選 |
| 描画方式 | 論理座標系（幅1000単位）＋ `ctx.setTransform` でスケール | プレビューと書き出しの差 0.159%、差分は文字の縁のみ |
| 書き出し形式 | JPEG q0.92 ＋ `piexifjs` で元 EXIF を再注入 | 249ms / 623KB。WebP は 3091ms で不採用 |
| **書き出し解像度** | **既定は長辺 4096px。設定で「元の解像度のまま」も選べる** | 6000x4000 は 1枚 100MB。iOS のタブ強制終了を避ける |
| 欧文書体 | OFL の代替8書体（Arimo/Jost/Oswald/Cinzel/Playfair Display/PT Serif/Tinos/Libre Baskerville） | 計 237KB。6書体は可変フォントで Bold が同一ファイル |
| **和文フォント** | **常用漢字＋かな＋記号の固定サブセットを同梱。同梱外の文字が入力されたときだけ、確認のうえ Google Fonts から取得** | 普段は通信ゼロ・オフライン可。フルセットは 4.98MB で同梱不可 |
| 縦書き | SVG `writing-mode: vertical-rl` を画像化して合成 | 約物が正しく組まれる。**`foreignObject` は禁止**（canvas が汚染され書き出しが失敗） |
| **撮影地** | **オフライン同梱のみ。日本の全市区町村（gzip 33KB）＋世界の主要都市（人口1.5万以上・24,323件、gzip 0.47MB）** | GPS 座標を外部に出さない。代表点の最近傍で引くため境界付近で誤差あり |
| 一括処理 | Web Worker + OffscreenCanvas で逐次処理、ZIP にまとめて保存 | メインスレッド 60fps 維持。連続ダウンロードは 10 件でブロックされる |
| **HEIC** | **実機検証まで判断を保留。** EXIF が取れない場合に手入力で補える設計を先に用意する | iOS が選択時に JPEG へ自動変換する可能性があり、その場合は対応不要 |

### 実装で必ず守る安全装置（実測で判明した罠）

1. **キャンバス生成直後に 1px 書き込み→読み戻しで検証する。** 面積上限（Chromium で 2^28）を
   超えると例外を投げず、全API が成功を装ったまま透明な黒を返す。
2. **フォントは `fillText` の前に `await` する。** 待たずに描くと警告なくフォールバック書体で
   書き出される。`document.fonts.check()` は描画後には true を返すため検知に使えない。
3. **フル解像度の処理は必ず1枚ずつ行い、都度破棄する。** 画像1枚で約100MBを消費し、
   この消費は `performance.memory` に現れない。
4. **グレインは論理座標に対する相対サイズで定義する。** 物理ピクセル固定だと、
   書き出しを縮小した時に粒の強さが約89%失われ、プレビューと一致しなくなる。
5. **Worker 内では `FontFace` コンストラクタ＋ `self.fonts.add()` を使う。** `document` が無いため
   DOM の `@font-face` は使えない。
